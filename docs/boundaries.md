# Boundaries

This repository is the thin public hub for the Jankurai split family. The
machine-readable maps live under `agent/`; this document is their prose
companion.

## Domain

The hub carries no product domain code. It owns family coordination data
(`repos.manifest.toml`, `family.lock`), distribution surfaces (`action.yml`,
`jankurai-installer.sh`), and the local fusion and validation scripts under
`scripts/`. There is no Rust crate, web surface, PostgreSQL database, or Python
AI/data service committed here, so those stack arms of the family standard are
not applicable.

## Forbidden cross-repo coupling

The hub must never commit cross-repo `path = "../..."` dependencies. Local
path patches are written only into the generated `.fusion/` workspace produced
by `scripts/fuse.sh`. Committed manifests must depend on immutable tags and
commit SHAs recorded in `family.lock`, never on sibling checkout paths or
branches. `scripts/validate-family.sh` enforces this on every run.

## Generated zones

Generated output is never hand-edited. The generated zones in this repo are
`target/` (local audit/CI state) and `.fusion/` (the fused workspace), declared
in [`agent/generated-zones.toml`](../agent/generated-zones.toml). Both are
regenerated by their declared command and ignored by git.

## Ownership and proof

- [`agent/owner-map.json`](../agent/owner-map.json) assigns an owner to every
  real top-level path.
- [`agent/test-map.json`](../agent/test-map.json) routes each owned path to the
  deterministic proof command `bash scripts/validate-family.sh`.
- The runnable lanes are defined in the root [`Justfile`](../Justfile); every
  lane command executes in this repo alone.

## Reclassification

If a future change adds a Rust, web, database, or Python surface to the hub,
update this document and the `agent/` maps first to declare the new boundary,
then add matching owner, test, and proof entries before landing the code. Such
deviations follow the exception pattern in [`docs/exceptions.md`](exceptions.md).
